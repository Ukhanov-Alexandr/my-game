# Архитектура игры «Зеркала и луч»

Это план: из каких частей состоит игра и как они связаны. Код пишется параллельно в разных папках, поэтому здесь описаны договорённости, а не готовые функции.

## Идея игры

На клетчатом поле стоит фонарь, он светит лучом. Игрок поворачивает зеркала, чтобы луч попал во все кристаллы. Все кристаллы освещены — уровень пройден.

## Главный принцип

**Правила игры отделены от отрисовки.**

- Правила — это обычные функции: они берут уровень (данные) и возвращают новый результат. Они ничего не знают про экран, мышь и звук.
- Интерфейс только рисует то, что посчитали правила, и передаёт им действия игрока.

Зачем так: правила можно проверять тестами за доли секунды без браузера, а внешний вид можно менять, не боясь сломать игру.

## Схема

```
        игрок (клавиши, тапы, свайпы)
                    |
                    v
   +-------------------------------+        +-------------+
   |  src/ui + index.html          | -----> |  src/audio  |
   |  рисует поле на canvas,       |  звук  |  Web Audio  |
   |  ловит ввод                   |        +-------------+
   +-------------------------------+
        ^                    |
        | новый level        | rotateMirror(level, x, y)
        |                    v
   +-------------------------------+
   |  src/core  (чистые функции)   |
   |  traceBeam, rotateMirror,     |
   |  isSolved, solve              |
   +-------------------------------+
        ^                    ^
        | level              | level
   +-------------+     +-------------------------------+
   | src/levels  |     | src/daily                     |
   | ручные      |     | дата -> сид -> генератор      |
   | уровни      |     | -> level (одинаков у всех)    |
   +-------------+     +-------------------------------+
```

Стрелки показывают, кто кого использует. `core` ни от кого не зависит — это ядро.

## Части и папки

| Папка | Что делает |
|---|---|
| `src/core` | Правила. Чистые функции без DOM: `traceBeam`, `rotateMirror`, `isSolved`, `solve` (поиск решения — нужен генератору и проверке уровней). |
| `src/levels` | 10+ уровней, придуманных вручную, в виде данных. |
| `src/daily` | «Уровень дня»: по дате получаем число-сид, по сиду генератор строит уровень. Один и тот же день даёт один и тот же уровень на любом устройстве. Генератор проверяет через `solve`, что уровень проходим. |
| `src/ui`, `index.html`, `style.css` | Отрисовка на canvas, клавиатура, тапы и свайпы, экран выбора уровня. |
| `src/audio` | Звуки на Web Audio (без файлов): поворот зеркала, победа. |
| `tests/` | Тесты на встроенном `node --test`, по папке на каждую часть: `tests/core`, `tests/levels` и т. д. |
| `.github/workflows` | CI (запуск тестов при каждом PR) и автодеплой на GitHub Pages. |

## Как описан уровень

Уровень — простой объект, его легко хранить и сравнивать:

```
{ width, height, cells }
```

Каждая клетка — одна из: `empty` (пусто), `wall` (стена), `emitter` (фонарь, у него есть `dir` — `up/right/down/left`), `mirror` (зеркало `/` или `\`, может быть `locked` — тогда его нельзя крутить), `crystal` (кристалл).

Функции правил не меняют уровень «на месте»: `rotateMirror` возвращает новый уровень. Благодаря этому легко сделать отмену хода.

## Что происходит за один ход

1. Игрок нажал клавишу, тапнул или свайпнул по зеркалу (`src/ui`).
2. UI вызывает `rotateMirror(level, x, y)` и получает новый уровень.
3. UI вызывает `traceBeam(level)` и получает путь луча и список освещённых кристаллов.
4. UI перерисовывает поле и проигрывает звук (`src/audio`).
5. Если `isSolved(level)` вернул `true` — показываем победу.

## Уровень дня

`дата (например 2026-11-09) → число-сид → генератор → level`. Нельзя использовать `Math.random()`: он у каждого игрока даёт своё. Нужен генератор псевдослучайных чисел, который по одному сиду всегда выдаёт одну и ту же последовательность.

## Тесты и выкладка

- Любое изменение правил идёт вместе с тестом.
- Запуск локально: `node --test`.
- CI запускает тесты на каждый PR; после слияния в основную ветку workflow выкладывает сайт на GitHub Pages.
- Никаких сборщиков и npm-зависимостей: файлы лежат как есть, JS подключается как ES-модули.

## Кто за что отвечает

Каждый тред работает только в своей папке (см. таблицу выше), чтобы параллельные правки не конфликтовали. Общие файлы (`README.md`, `index.html`) меняются только с пометкой об этом в описании PR.
